What went wrong
Fix now
The subscriptions table stores records for multiple clients, but there is no database rule enforcing that each client can only see their own records. Any client query could inadvertently (or intentionally) read another client's subscriptions.
This was also confirmed on your live test site: a test probe logged in as one user and retrieved subscription records belonging to a different account. The fix must be applied in the database, not just the application code.
Code evidence
src/db/schema/subscriptions.ts
// Table stores per-client records but has no row-level security rule export const subscriptions = pgTable('subscriptions', { id: uuid('id').defaultRandom().primaryKey(), organisationId: uuid('organisation_id').notNull(), // per-client field planId: text('plan_id').notNull(), status: text('status').notNull(), }); // No corresponding enableRls() + createPolicy() found in any migration file

How to fix this
Add a Postgres row-level security policy to the subscriptions table in the Drizzle migration. The policy should restrict reads and writes to rows where the per-client field matches the current user's client ID from their session token.
// Before: no access rule, all clients can read all rows export const subscriptions = pgTable('subscriptions', { organisationId: uuid('organisation_id').notNull(), ... }); // After: add to migration file await sql`ALTER TABLE subscriptions ENABLE ROW LEVEL SECURITY`; await sql` CREATE POLICY subscriptions_tenant_isolation ON subscriptions USING (organisation_id = current_setting('app.current_org_id')::uuid) `;
